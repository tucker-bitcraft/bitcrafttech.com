**Echo** is a locally-deployed AI assistant built for persistent context,
modular capability, and real agency. It runs on open-weights models on dedicated
hardware — it doesn't phone home. This section is the reference documentation for
Echo and the components around it, the same software featured in the
[Lab](/lab).

## The stack at a glance

Echo is not one program but a small constellation of cooperating components, each
with a single responsibility:

| Component | Responsibility |
|---|---|
| **Echo Core** | The cognitive loop — perception, reasoning, and decision-making. |
| **Medulla** | Skill dispatch. Exposes callable capabilities ("Ports") to the outside world. |
| **HippoDB** | Long-term memory. Graph-native, temperature-tiered (hot → warm → cold → archive). |
| **Scratchpad** | Ephemeral working memory for a single reasoning session. |

## How a thought becomes an action

At a high level, one cycle of Echo's loop looks like this:

1. **Perceive** — input arrives (a message, a sensor event, a timer).
2. **Recall** — relevant memories are pulled from **HippoDB** into **Scratchpad**.
3. **Reason** — Echo Core works the problem in Scratchpad's structured buckets.
4. **Act** — when a decision is made, **Medulla** turns it into a real effect via a Port.
5. **Commit** — what mattered is written back to HippoDB; the rest dissolves.
